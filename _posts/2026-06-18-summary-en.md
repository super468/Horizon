## [RFC 10008: New HTTP QUERY Method Standardized](https://www.rfc-editor.org/info/rfc10008/) ⭐️ 8.0/10

The IETF has published RFC 10008, standardizing a new HTTP QUERY method that provides an idempotent alternative to GET for requests requiring a request body. This addresses long-standing limitations in HTTP's method design where GET historically didn't support request bodies while POST supports bodies but isn't idempotent. This enables developers to send complex query parameters (like JSON filtering structures or image inputs) in the request body while maintaining idempotency, allowing safe automatic retries. It will significantly impact API design, caching strategies, and could enable HTML forms to avoid the annoying re-submission warnings seen with POST. QUERY requests that the target process the enclosed content in a safe and idempotent manner and respond with the result. Unlike POST, QUERY can be automatically repeated or restarted without concern for partial state changes. The method is part of the HTTP Standards Track.

hackernews · schappim · Jun 17, 10:51

**Background**: HTTP methods are classified as idempotent if multiple identical requests have the same effect as a single request. GET, PUT, DELETE are idempotent, while POST is not. The HTTP working group previously considered allowing GET with a body but rejected it due to historical interoperability issues and compliance with HTTP's core architectural definitions. RFC numbers have now reached 5 digits.
