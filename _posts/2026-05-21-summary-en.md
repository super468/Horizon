## [Mozilla Deprecates asm.js After Pioneering Web Performance](https://spidermonkey.dev/blog/2026/05/20/saying-goodbye-to-asmjs.html) ⭐️ 8.0/10

Mozilla officially announced the deprecation and complete removal of asm.js from SpiderMonkey, their JavaScript engine. asm.js was a restrictive subset of JavaScript that Mozilla created to enable near-native performance in browsers, serving as a proof-of-concept that directly inspired the creation of WebAssembly. 这标志着一个关键的网页技术的正式终结，它填补了JavaScript与原生代码性能之间的空白。asm.js使得像Figma这样的先锋项目能够证明复杂的设计工具可以在浏览器中运行，其设计理念直接推动了WebAssembly成为网页高性能代码执行的标准。 asm.js worked by imposing strict constraints on JavaScript semantics—disabling garbage collection, requiring typed arrays, and enforcing static memory allocation—which allowed compilers like Emscripten to generate highly optimized code. While revolutionary, it required parsing full JavaScript ASTs and resulted in larger bundle sizes compared to WebAssembly's binary format.

hackernews · eqrion · May 20, 12:01

**Background**: asm.js was introduced around 2013 as Mozilla's answer to Google's Native Client (NaCl/PNaCl), which aimed to run native C/C++ code securely in browsers but wasn't cross-browser compatible. Unlike NaCl, asm.js was pure JavaScript that ran in any browser while still achieving near-native speeds. It became a crucial stepping stone that demonstrated both the feasibility and the approach for what would eventually become WebAssembly.

## [Formal Verification Gates for AI Coding Agents](https://reubenbrooks.dev/blog/structural-backpressure-beats-smarter-agents/) ⭐️ 8.0/10

A blog post proposes using type systems and formal verification as "structural backpressure" to constrain AI coding agents, ensuring they produce correct outputs by enforcing strict type signatures and proofs before code can compile. This approach addresses the reliability problem of LLM-generated code by making incorrect outputs literally uncompilable, potentially transforming how AI-assisted coding is practiced in safety-critical industries. The author suggests using dependent types and theorem provers (like Lean) where AI agents must provide proofs that functions satisfy their specifications - if the proof fails, the code won't compile. Community critics note that the JWT verification example only checks token non-emptiness, not actual expiration or signature validity.

hackernews · pyrex41 · May 20, 15:25

**Background**: Formal verification uses mathematical logic to prove program correctness, distinct from testing which only checks selected cases. Dependent types can encode arbitrary predicates into type signatures, allowing the type system to reject programs that don't meet specifications. TLA+ is a formal specification language used by companies like AWS for verifying concurrent systems.
