## [llama.cpp b9510 为量化点积添加 WASM SIMD 向量化](https://github.com/ggml-org/llama.cpp/releases/tag/b9510) ⭐️ 7.0/10

这一优化显著提升了 WebAssembly 部署的推理性能，WebAssembly 常用于浏览器中的 LLM 应用。这个关键量化内核上 3.42 倍的加速直接转化为网络环境中更快的令牌生成，llama.cpp 在这些环境中的应用日益增多。 该实现使用 wasm_v128_load 在单次操作中覆盖所有 32 个打包的 4 位权重，通过 AND/SHR 将 nibble 解包到两个 u8x16 寄存器，在乘法前扩展到 i16，因为 WASM SIMD 没有 i8×i8 指令。四次 wasm_i32x4_dot_i16x8 调用累积所有 32 个元素对，然后通过 wasm_i32x4_extract_lane 进行水平约简。正确性已通过 10 个随机种子与标量参考实现的精确输出一致性验证。

github · github-actions[bot] · Jun 4, 14:44

**背景**: llama.cpp 是一个纯 C/C++实现，用于在各种硬件平台上进行高效的 LLM 推理，包括 WebAssembly。WebAssembly (WASM) 允许在浏览器中以接近原生的性能运行编译后的代码，使其在无服务器 AI API 和基于浏览器的 LLM 演示中很受欢迎。SIMD128 是 WebAssembly 的 128 位单指令多数据扩展，允许并行处理多个数据元素。Q4_1 和 Q8_1 是 GGML 中的量化格式，分别将模型权重压缩到 4 位和 8 位，同时保持合理的精度。

一篇技术评论认为，嵌入在 URL 中的 IPv6 区域标识符（如%eth0）是一个设计错误，理由是存在严重的安全漏洞——shell 元字符可以有效地存在于区域 ID 字符串中，而且浏览器支持不一致，导致许多本地网络设备无法访问。 RFC 6874 规定使用百分号编码来表示 IPv6 区域 ID（例如 fe80::1%eth0 变成 fe80::1%25eth0），但浏览器对此处理不一致——Firefox 在 WHATWG 拒绝后完全移除了该功能，而 Chrome 据称从未实现它，用户不得不使用_ipv6_proxy 等项目作为代理。

hackernews · xena · Jun 4, 21:42
