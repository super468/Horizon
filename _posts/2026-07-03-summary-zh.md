## [crustc：将 Rust 编译器翻译为 C](https://github.com/FractalFir/crustc) ⭐️ 7.0/10

一位开发者花费 3 年创建了 crustc，这是一个将整个 Rust 编译器(rustc 1.98.0-nightly)转换为约 4600 万行 C 代码的转译器，使 Rust 能够在没有 LLVM 或 GCC 工具链支持的硬件上编译。 这个项目通过提供替代路径来解决 Rust 的自举问题，无需依赖现有的 Rust 编译器即可编译 rustc。它还使 Rust 能够支持缺乏现代编译器工具链的旧的和 obscure 的硬件平台，这对嵌入式系统和安全敏感环境具有重要意义。 crustc 将 rustc 转换为可以用 GCC 和 make 构建的 C 代码。该开发者多年来进行了多次公开尝试，包括 rustc_codegen_clr。转译后的 C 代码代表了一个可以理论上自我编译的功能性 Rust 编译器。

hackernews · Philpax · Jul 2, 22:57

**背景**: 自举是一种编译器技术，编译器用自己编译的语言编写，从而创建一个自编译编译器。Rust 通常需要现有的 rustc 才能从源代码构建 rustc，从而形成循环依赖。该项目通过输出可以用传统 C 编译器(如 GCC)编译的 C 代码来解决这个问题，无需 LLVM 或现有的 Rust 工具。

## [Linux 6.9 LUKS 挂起安全回归问题](https://mathstodon.xyz/@iblech/116769502749142438) ⭐️ 7.0/10

Linux 6.9 引入了一个安全回归问题，LUKS 磁盘加密密钥在挂起时不再从内存中清除。该功能可能是 Debian 扩展，而不是官方支持的内核功能。 此回归影响使用 LUKS 全磁盘加密系统的安全性。如果加密密钥在挂起期间保留在内存中，攻击者可能通过物理访问或恶意软件提取密钥。讨论凸显了官方支持功能与发行版特定扩展之间的不确定性。 该问题已被发现，并添加了 NixOS 测试以防止回归。这影响挂起（睡眠到 RAM），而不是休眠（挂起到磁盘），后者会正确加密和清除 RAM 内容。

hackernews · IngoBlechschmid · Jul 2, 15:25

**背景**: LUKS（Linux 统一密钥设置）是一种磁盘加密规范，为 Linux 系统实现透明的全磁盘加密。cryptsetup luksSuspend 命令旨在挂起期间通过从内核内存中清除加密密钥来暂停磁盘加密。此安全措施可防止在机器挂起时被入侵时提取密钥。
