## [Mozilla 淘汰 asm.js：开创浏览器性能的先驱技术落幕](https://spidermonkey.dev/blog/2026/05/20/saying-goodbye-to-asmjs.html) ⭐️ 8.0/10

Mozilla 正式宣布在 SpiderMonkey JavaScript 引擎中移除并淘汰 asm.js。asm.js 是 JavaScript 的一个受限子集，由 Mozilla 创建用于实现浏览器的原生级性能，这一技术直接启发了 WebAssembly 的诞生。 asm.js 通过严格约束 JavaScript 语义来实现优化——禁用垃圾回收、要求使用类型化数组、强制静态内存分配——这使 Emscripten 等编译器能够生成高度优化的代码。虽然具有革命性，但它需要解析完整的 JavaScript 抽象语法树，且生成的包体积比 WebAssembly 的二进制格式更大。

hackernews · eqrion · May 20, 12:01

**背景**: asm.js 大约在 2013 年推出，是 Mozilla 针对谷歌的 Native Client（NaCl/PNaCl）问题的回应，后者旨在浏览器中安全运行原生 C/C++代码但缺乏跨浏览器兼容性。与 NaCl 不同，asm.js 是纯 JavaScript，在任何浏览器中都能运行且能达到接近原生的性能。它成为了关键的垫脚石，证明了最终成为 WebAssembly 的技术方案的可行性。

## [AI 编码代理的形式化验证门控](https://reubenbrooks.dev/blog/structural-backpressure-beats-smarter-agents/) ⭐️ 8.0/10

一篇博客文章提出使用类型系统和形式化验证作为"结构性反压"来约束 AI 编码代理，通过在代码编译前强制执行严格的类型签名和证明来确保生成正确的输出。 这种方法通过使不正确的输出在字面上无法编译来解决 LLM 生成代码的可靠性问题，可能会改变人工智能辅助编程在安全关键行业中的实践方式。 作者建议使用依赖类型和定理证明器（如 Lean），AI 代理必须提供函数满足其规范的证明——如果证明失败，代码将无法编译。社区批评者指出，JWT 验证示例只检查令牌非空，而非实际的过期时间或签名有效性。

hackernews · pyrex41 · May 20, 15:25

**背景**: 形式化验证使用数学逻辑来证明程序正确性，这与仅检查选定用例的测试不同。依赖类型可以将任意谓词编码到类型签名中，允许类型系统拒绝不符合规范的程序。TLA+是一种形式化规范语言，被 AWS 等公司用于验证并发系统。
