## [Rosenbridge Hardware Backdoor in VIA C3 Processors](https://github.com/xoreaxeaxeax/rosenbridge) ⭐️ 7.0/10

The Rosenbridge project reveals a hardware backdoor in some VIA C3 x86 processors that allows unprivileged (ring 3) code to escalate to kernel (ring 0) privileges, bypassing standard security boundaries. This discovery raises fundamental questions about trust in closed-source CPUs, with implications that extend to modern processors like Intel ME and AMD PSP. As hardware complexity increases and more vendors produce poorly documented chips, this research highlights the growing risk of undetectable hardware-level vulnerabilities. The backdoor specifically affects VIA C3 embedded processors, a decades-old x86 CPU family. Researchers provide tools to detect and potentially disable this vulnerability. Debate exists in the security community about whether this is truly a backdoor or an undocumented CPU feature.

hackernews · epestr · Aug 8, 07:04

**Background**: Rosenbridge is a research project demonstrating a hardware backdoor in certain x86 CPUs, primarily the VIA C3 processor family. The VIA C3 (Cyrix III) is an x86-compatible microprocessor used in embedded systems. In x86 architecture, CPUs operate in different privilege rings: ring 0 is kernel mode with full system access, while ring 3 is user mode with limited privileges. This backdoor allows code in ring 3 to jump to ring 0, circumventing normal privilege escalation protections. Similar concerns exist around Intel Management Engine (ME) and AMD Platform Security Processor (PSP) - coprocessors that run with even higher privileges than the main CPU and cannot be disabled by users.

## [Critical macOS Screen Sharing Vulnerability Allows Passwordless Access](https://x.com/calif_io/status/2086022794840793454) ⭐️ 7.0/10

Security researchers disclosed a critical macOS screen sharing vulnerability (CVE-2026-65400) that allows unauthenticated network attackers to gain access to any account without knowing the password. Apple has patched this vulnerability in macOS 26.6.1, as well as macOS 15.7.9 and 14.8.9. This is a critical security flaw because it allows remote attackers to execute arbitrary code with root-level privileges without any authentication. Any Mac with screen sharing enabled is vulnerable to complete system compromise by network attackers. The vulnerability was resolved through improved state management in the screen sharing function. Researchers have reverse-engineered the patch to understand the root cause and exploitation path, with a full technical analysis expected to be published tomorrow.

**Background**: macOS screen sharing uses the VNC (Virtual Network Computing) protocol, which typically requires password authentication to prevent unauthorized access. This vulnerability bypasses the normal authentication mechanism entirely, allowing anyone on the network to connect without credentials.
