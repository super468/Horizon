## [GitHub 堆叠式拉取请求正式进入公开预览](https://github.blog/changelog/2026-07-30-stacked-pull-requests-are-now-in-public-preview/) ⭐️ 8.0/10

GitHub 已正式推出堆叠式拉取请求的公开预览功能，使开发者能够在堆叠中创建相互依赖的拉取请求，这被誉为 GitHub 历史上规模最大的发布之一。 这标志着 GitHub 拉取请求模式的重大变革，可能会影响数百万开发者，实现更精细的代码审查，更好地管理大型复杂变更。 堆叠式拉取请求允许开发者将大型变更分解为小型、可审查的有序拉取请求系列。每个 PR 代表变更的专注层，可以独立审查。用户可以通过 GitHub UI、API 或使用 gh stack 扩展的 CLI 创建和管理堆叠式拉取请求。该功能依赖变基而非合并提交来保持差异清晰。

hackernews · tomzorz · Jul 30, 16:26

**背景**: 堆叠式拉取请求是一种工作流模式，开发者创建一系列相互依赖的 PR，每个 PR 都基于前一个 PR。这允许对每一层进行独立审查，同时保持整体变更历史。这种方法在 Google 等大型代码库中很受欢迎，Graphite 和 git-branchless 等工具此前也提供过类似功能。

## [GCC 指导委员会宣布人工智能政策](https://lwn.net/Articles/1086041/) ⭐️ 8.0/10

GCC 指导委员会宣布了一项人工智能贡献政策，将拒绝任何包含 LLM 生成内容或文本的具有法律意义的贡献，同时对 LLM 生成的测试用例例外。该政策将于 2027 年初重新审议。 这一政策代表了主要开源项目对人工智能生成代码的正式立场，直接解决了影响 GPL 许可的版权问题。它反映了更广泛行业在人工智能伦理、知识产权和机器生成内容的法律影响方面的挣扎。 政策规定 GCC 将拒绝包含 LLM 生成内容的具有法律意义的贡献，但维护者可以接受 LLM 生成的测试用例。这与现有 GNU 阻止 AI/LLM 贡献的政策一致。该决定源于 LLM 输出可能根据现行美国法律不受版权保护，这与基于版权的 GPL 许可模式相冲突。

hackernews · arto · Jul 30, 11:45

**背景**: GCC（GNU 编译器集合）是最重要的开源编译器套件之一，支持多种编程语言和平台。由理查德·斯托曼创立的 GNU 项目遵循自由软件理念运营，GPL（通用公共许可证）是其主要许可证。该政策解决了围绕人工智能生成内容版权性的法律不确定性，因为美国法院已表示没有人类作者的 LLM 输出无法获得版权。

## [研究发现 LLM 架构存在根本性无法修复的缺陷](https://www.technologyreview.com/2026/07/30/1140927/a-fundamental-flaw-leaves-llms-vulnerable-to-attack/) ⭐️ 8.0/10
