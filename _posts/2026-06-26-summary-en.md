## [PostgreSQL 19 Beta Adds SQL Graph Queries and Concurrent Repack](https://www.infoq.cn/article/HOFzjxIov0SxEpmZccYT?utm_source=rss&utm_medium=article) ⭐️ 8.0/10

PostgreSQL 19 beta introduces native SQL graph query support through the SQL/PGQ standard (ISO/IEC 9075-16:2023) with GRAPH_TABLE syntax, enabling graph queries over existing relational tables without requiring a separate graph database. It also adds the REPACK command with CONCURRENTLY option for online table maintenance that absorbs VACUUM FULL and CLUSTER functionality. This marks PostgreSQL's entry into graph data processing, enabling users to handle graph workloads without migrating to a separate graph database. The concurrent repack also solves long-standing pain points where VACUUM FULL and CLUSTER required exclusive table locks, making table maintenance production-friendly. SQL/PGQ is optimized for shallow, fixed-depth graph queries which represent the majority of graph queries in production systems. The REPACK command physically compacts tables by rewriting them into new storage files, and PostgreSQL 19 extends the asynchronous I/O framework from v18 with automatic scaling of I/O workers.

rss · InfoQ 中文站 · Jun 25, 11:03

**Background**: Graph databases are specialized for storing and querying interconnected data like social networks, recommendation engines, and fraud detection systems. SQL/PGQ is the ISO standard for SQL graph query extensions, and PostgreSQL implements it through GRAPH_TABLE which projects relational data as graph structures. REPACK addresses the issue of dead tuples left behind by UPDATE and DELETE operations that degrade performance over time.
